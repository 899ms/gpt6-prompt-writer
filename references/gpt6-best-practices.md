## 五类机制如何改变提示词

| 来源观察（S1） | 本技能的转化 | 需要观察的信号 |
| --- | --- | --- |
| GPT‑6 更可能在补充信息能改变结果时发问 | 定义哪些缺项可假设、哪些必须澄清；写清实际交付物，持续完成已授权工作 | 有足够信息时交付产物，关键歧义仍会指出 |
| 对 Skill / AGENTS.md 等上下文指令更敏感 | 审查冲突与暂停来源；区分技能建议和高优先级指令 | 不能把技能中的例行确认误当成新的硬门槛 |
| 可能偏长、偏多格式及重复措辞 | 明确读者、篇幅、段落/列表选择，给一个必要的风格样例 | 符合用户长度和格式，无套话膨胀 |
| 多代理委派可能少于应用预期 | 有已授权的多代理环境时，明确委派对象与分工条件 | 委派独立任务，主代理检查与整合结果 |
| 编码验证可能过度 | 定义必要检查与扩大测试的触发，完成后停止 | 检查相关行为，避免无变化的重复测试 |

其中，最小任务契约、按需模块、默认一个版本和三类反测是本技能的工程设计，不能称为 OpenAI 官方规定。

## S5 如何合并到已有规则

| 检索到的最近资产 | 原有不足 | 本次落点 |

| 模块 A 的完成标准 | 对运行、检查产物、修复失败的覆盖不够显式 | 根据用户任务补全交付链及停止信号，移除无必要的中途复核 |

不吸收为全局规则的内容：模型更强不意味着无条件安全、无需测试或可以扩大权限；文章没有规定统一描述长度、禁止所有固定流程，也没有证明本技能的实际效果。共享指令必须保留目标模型差异。

## 指令优先级的准确解读

S1 建议避免技能指南压过用户明确意图；S2 同时明确开发者消息优先于用户消息。因此，采用“先服从平台系统与开发者约束，再在这些约束内执行用户任务；技能建议用于协助任务”。不能缩写成“用户覆盖一切指令”。

如技能规则实际造成停顿，应明确文件、具体条款和适用理由。此透明要求不等于为每次读文件增加一轮确认。

## 自主性不是扩大授权

把自主性落实成：常规选择可自行决定；已经授权的可逆步骤继续；需要审批的发布等动作先准备可审阅产物；阻塞只影响依赖它的步骤。先前已明确授权的同一动作不重复索取许可。

遇到新的用户补充时，结合上下文更新任务要求，保留仍有效的目标和已有工作。实际 API 的 mid-turn steering、异步工具与配置更新需要应用实现，不由文字提示词启用。

## 来源刷新

1. 用户要求最新或请求真实 API 配置时，检索并打开 S1；确认当前内容仍指向目标模型。
2. 若入口换代，继续查已指定的 GPT‑6 Astra。未核验前保留本快照，不替换成其他模型的限制。
3. 参数、Structured Outputs 和角色行为只读相关 S2–S4 章节，必要时跟进具体模型页。
4. 网络不可用时按实际引用的来源标明快照日期，将新参数主张暂缓；普通提示词仍可交付。S5 的读取日期不刷新 API 核验日期。
5. 来源冲突时优先更具体、当前的模型页；无法确定则标明冲突，不揉成一个无来源结论。
