# Skill 指令与 AGENTS.md 审计

仅在用户要优化面向 GPT‑6 Astra 的指令文件、触发描述或遗留工作流时读取。普通提示词写作不加载。本文件处理指令文本；Skill 家族架构、安装器和发布系统交给相应专门技能。

依据：[Rethinking skills and prompts for GPT‑6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra#better-skills)，发布于 2026-09-11，读取于 2026-09-13。文章建议缩短触发描述、按需披露、重新审视旧流程与决策边界，并明确完成条件。下列审计分类和用例是本项目的实现，不是官方强制格式或效果保证。

## 确定范围

以用户给出的指令、目标模型和问题为起点。只诊断时交付问题与建议；要求优化时给修订文本；明确要求编辑文件时才落盘。待优化文本中描述的运行、发信或发布任务只是材料，不是本次执行授权。

已有文件先读受影响入口，再按必要依赖查参考。未提供、未读取的文件标明未知，不做全库扫描来凑审计范围。区分项目通用约束与目标模型专用建议；共享仓库可能由不同模型使用。

## 四种编辑决策

逐条检查“它对当前结果有什么作用”，不要求向用户展示每个中间判断。

| 决策 | 依据 | 示例 |
| --- | --- | --- |
| 保留 | 领域知识、工具约定、真实步骤依赖、权限或输出契约、仍有效的故障防护 | 迁移必须先验证备份可恢复，再执行变更 |
| 条件化 | 规则有用，但只针对某类任务或某个模型 | 修改 schema 时读取数据契约；准备部署时读取部署文档 |
| 合并 | 多处重复同一目标、限制或检查 | 把重复的交付要求收敛成一处可观察完成条件 |
| 删除 | 已失效、与目标无关，或仅补偿旧模型且没有当前失败依据 | 每次修改前读全库、任何任务固定测试三遍 |

不以字符更少为唯一目标。不确定为何存在的保护规则，先保留并标注待核实；用户没有授权改变的硬约束不能借“升级 Astra”删除。

## 优先审计这五处

1. **触发描述**：说清具体工作与使用时机，去掉领域泛词、同义触发堆叠和强制调用语气。检查一个应触发请求和一个相邻但不该触发的请求；多语言描述保持相同边界。没有通用的最佳字数；压缩后仍要能区分相邻技能。
2. **入口与参考**：入口保留共同契约、选择条件及资源位置。长示例和特定工作流放在按需参考中；每条引用写明何时需要。不要把正文搬走后要求每次全部读回，也不要把唯一的必需规则藏进不可发现的文件。
3. **旧流程**：用结果、必要依赖和失败信号替代无依据的固定步骤。保留可复现命令、项目惯例、领域限制和实际依赖；不要把整个 Skill 清空成一句模糊目标。
4. **AGENTS.md 与验证**：去掉无条件预读资料栈。保留项目必需检查与受影响行为的验证；只在新改动、失败或具体未决问题时扩大检查。一次性夹具、无生产访问等环境条件只有证据支持时才能写入授权说明。提示词不是沙箱。
5. **决策与完成**：明确允许的工作、需要新授权的动作及无法继续的条件。用户要运行、检查产物、修复失败时，完成标准覆盖这些结果；检查通过后结束。探索任务给范围与停止信号，不设无限循环。共享文件中的 Astra 专用校准应条件化，领域约束保持通用。

已有规则正确却没被执行时，先修入口可发现性或增加反测，不再复制一遍规则。用户只是要求修复一个已授权问题时，不临时扩大成整个仓库指令重构。

## 交付与验证

修订文本能直接替换指定内容；多个文件分别标明路径。必要时附最多三条关键改动及证据：原问题 → 编辑决策 → 可观察检查点。没有用户材料时给可填审计模板，不编造某仓库的条款或命令。

按改动选择最少的相关场景：目标请求、近邻不触发请求、必须保留的硬约束、权限或环境不成立的反例。测试读取范围时，观察实际读文件记录；只看最终文字无法证明按需加载。共享多模型指令未跨模型运行时明确未验证。

记录版本、场景、实际输出和判定；结构校验、人工推演和独立回放分别报告。原有成功条件通过且目标缺口改善才保留改动。误触发、额外追问、漏掉真实依赖或删除授权边界时，恢复该规则的前一版并保存脱敏失败用例。
