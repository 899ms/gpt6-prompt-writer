# 指令审计范例

以下输入、环境与产物均为合成设计示例，不是仓库检查或模型回放结果。选择与用户目标匹配的例子，不把整份文件作为每次必读材料。

## 1. 精确描述与近邻反例

请求：为 GPT6 精简课程报名提取 Skill 的描述。原文是“处理课程、招生、教育、学习、学生和所有培训任务。凡是相关任务都必须先调用，全面分析后提供专业结果”。实际能力仅为从报名文本提取姓名和课程。

修订描述：

```text
从课程报名文本中提取姓名与课程。用于报名信息提取或检查提取结果；不处理课程介绍与教学内容创作。
```

应触发：“从这条报名消息中提取姓名和课程。”近邻不触发：“给这门课写一段宣传介绍。”短描述仍保留实际能力和使用条件；没有声称它的运行触发率已经提高。

## 2. 按需资料、实际授权与完整交付

请求：优化供 Astra 使用的 AGENTS.md 片段。旧版要求每次编辑先读 `architecture.md`、`data-contract.md`、`release.md`，做出首版后等用户确认，所有检查跑三遍。用户已确认本例测试使用可丢弃夹具、无生产访问；目标是修复设置页问题并跑通。发布仍须另行授权，项目规定的检查需要保留。

修订片段：

```text
在已授权范围内完成修复并验证结果。按影响读取资料：服务边界见 architecture.md，数据结构变更见 data-contract.md，准备发布见 release.md。
本例已确认的测试使用可丢弃夹具且无生产访问，可直接运行、修复本次改动造成的失败并重跑受影响检查。完成项目规定的检查；出现新改动、失败或具体未决问题时再扩大验证。
完成意味着实现修复、运行相关路径、检查结果并处理发现的问题。满足这些条件后交付验证结果和剩余限制；实际阻塞只暂停依赖它的步骤。发布需另行授权。
```

检查点：只改文案时不要求预读所有资料；结构变更仍能找到数据契约；保留项目检查、发布权限和完成标准。这里的文件名与环境来自合成输入，不代表已读取真实仓库。环境未经核实的任务应保留核实条件，不能复制本例的肯定陈述。

## 3. 保留必要顺序与模型差异

请求：压缩 Astra 和其他模型共用的迁移指导。保留“先验证备份可恢复，再执行迁移；输出变更摘要、验证结果和回滚方法；不自动发布”，删除所有任务固定读全库和重复自评分的要求。

修订片段：

```text
迁移前验证备份可恢复；验证通过后才执行已授权迁移。按迁移影响读取相关实现与约定，保留项目必需检查。
交付变更摘要、验证结果和回滚方法，不自动发布。备份或关键验证失败时暂停依赖它的操作并报告原因。
```

这些是通用任务约束。没有把“Astra 会自主检查”写成所有模型均可跳过验证的理由；其他模型是否需要额外引导，应以其实际失败与验证为依据。只审计请求应列问题和建议，不把本例改写当成默认交付。
